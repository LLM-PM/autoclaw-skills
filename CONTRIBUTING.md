# Contributing

Thanks for contributing to AutoClaw Skills.

## Scope

Contributions should improve public skill behavior, documentation, compatibility, testing, or maintenance. Do not submit proprietary company material, customer data, private APIs, credentials, tokens, internal-only documentation, or other information you are not authorized to publish.

## Workflow

1. Open an issue for material behavior changes or new skills.
2. Keep changes narrowly scoped and explain the user-facing impact.
3. Update documentation when behavior changes.
4. Add or update validation notes for compatibility-sensitive changes.
5. Submit a pull request with a concise description and testing notes.

## Pull request expectations

A pull request should include:

- what changed;
- why the change is needed;
- any compatibility implications;
- any security or privacy considerations;
- how the change was validated.

The maintainer may request changes before merge when a contribution introduces ambiguous behavior, undocumented dependencies, security risk, or unclear licensing provenance.
